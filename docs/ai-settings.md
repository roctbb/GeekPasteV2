# Подключение ИИ

Администратор настраивает подключение в **Система → Настройки ИИ** (`/system/ai`).
Оно общее для проверки решений GeekPaste, включая изображения, и внешнего API проверки.

Два режима:

- **Собственный шлюз** — прежний протокол: `token` в JSON, настройки в `params`, ответ в `result.output`.
- **OpenAI API** — стандартный [Responses API](https://developers.openai.com/api/docs/guides/text):
  `Authorization: Bearer …`, поля `model`, `input`, `max_output_tokens`, `store: false`, ответ в `output`.
  По умолчанию адрес `https://api.openai.com/v1/responses`. Можно задать другой совместимый endpoint.
  Chat Completions (`/chat/completions`) этим режимом не поддерживается.

У каждого режима свои ключ, полный URL и необязательный сетевой прокси HTTP(S)/SOCKS5.
Прокси может содержать логин и пароль; весь его URL хранится как секрет и не возвращается в HTML.
Если прокси не задан, запрос идёт напрямую; переменные HTTP_PROXY/HTTPS_PROXY окружения не используются.
Редиректы API отключены, чтобы не передавать ключ другому адресу.
При ошибке провайдера переключения на другой сервис нет.

Модель, лимит токенов и таймаут задаются на той же странице. Модель конкретной задачи имеет приоритет
над общей. Требуется модель, поддерживающая Responses API и изображения, если задача принимает картинки.
Незавершённые ответы, ошибки API и отказы модели обрабатываются как ошибки проверки.
Существующие повторы сетевых ошибок Celery сохраняются; транспорт не добавляет свои повторы.

## Хранение и обновление

Настройки сохраняются в таблице `ai_settings` общей базы PostgreSQL. Web и Celery читают их перед
каждым запросом; перезапуск для изменения настроек не нужен. Уже начатые запросы используют свой снимок.
Данные переживают пересоздание контейнеров в существующем постоянном томе PostgreSQL.

Перед первым использованием установите зависимости и выполните `flask db upgrade` (в Docker это делает
сервис `migrate`). Миграция добавляет таблицу, не меняет решения и не копирует ключи из окружения.
До миграции проверки продолжают использовать окружение; сохранение через интерфейс недоступно.

Весь JSON настроек зашифрован Fernet. Используется `AI_SETTINGS_ENCRYPTION_KEY` (Fernet-ключ),
а если он отсутствует — ключ, полученный из постоянного `SECRET` приложения длиной не менее 32 символов.
Одинаковый ключ должен быть у web и worker. Храните его вместе с резервными копиями конфигурации:
смена ключа без переноса данных сделает сохранённые настройки нечитаемыми. При этом проверки завершаются
ошибкой, а не уходят на прежний шлюз. Администратор может сбросить настройки к окружению и ввести их заново.
Со слабым стандартным SECRET сохранять секреты нельзя.

Пустой ввод ключа/прокси сохраняет текущее значение. В списке действий можно явно удалить значение
(для прокси — отключить его) либо снова использовать соответствующую переменную окружения.
Кнопка общего сброса удаляет все переопределения. Доступ только у роли `admin`, изменения защищены CSRF.

## Значения окружения

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `AI_PROVIDER` | `gateway` или `openai`, по умолчанию `gateway` |
| `GPT_GATEWAY` | Полный URL существующего шлюза, прежнее значение сохранено |
| `GPT_KEY` | Ключ шлюза |
| `GPT_PROXY` | Сетевой прокси шлюза, по умолчанию пусто |
| `OPENAI_RESPONSES_URL` | `https://api.openai.com/v1/responses` |
| `OPENAI_API_KEY` | Ключ стандартного API |
| `OPENAI_PROXY` | Сетевой прокси стандартного API, по умолчанию пусто |
| `GPT_MODEL` | Прежняя модель по умолчанию, `gpt-5.6-luna` |
| `GPT_MAX_OUTPUT_TOKENS` | `8192` |
| `AI_TIMEOUT` | Таймаут HTTP-запроса, `180` секунд |
| `AI_SETTINGS_ENCRYPTION_KEY` | Необязательный отдельный Fernet-ключ шифрования |

До первого сохранения все значения берутся из окружения. После сохранения публичные поля задаются
через интерфейс, а невведённые ключи и прокси продолжают наследоваться из окружения.
