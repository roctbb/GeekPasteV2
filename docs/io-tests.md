# Тесты ввода/вывода

В разделе **Задачи → Создать / Редактировать** выберите тип проверки `tests`
и режим **Ввод / вывод — настройка в браузере**. Поддерживаются Python и C++.
Добавьте пары stdin / ожидаемый stdout, выберите публичность каждого теста и сохраните задачу.
Тесты можно удалять и переставлять стрелками. Пустые поля допустимы.

## Оценка и видимость

- **По доле пройденных тестов:** `points * passed // total`, округление вниз.
- **Всё или ничего:** полный балл только при прохождении всех тестов.
- **По группам:** группа даёт свой балл только при прохождении всех входящих в неё тестов.
  Каждый тест относится к одной группе; пустые группы не допускаются.
  Сумма баллов групп должна совпадать с максимальным баллом задачи.

Сохраняются действующие правила минимального балла за попытку и олимпиадных задач.
Например, обычная задача с режимом «Всё или ничего» при ошибке получает 1 балл
за попытку, как и раньше; статус полного выполнения выставляется только при
прохождении всех тестов. Неполная группа не получает частичных баллов.

Публичные тесты показываются ученикам на странице отправки решения.
При неверном ответе отчёт содержит ввод, эталон и фактический вывод.
Приватные тесты видны преподавателям в редакторе; в отчёте ученика остаётся только
результат. Их stdout, stderr, входные данные и эталон скрыты.
Названия групп видны только преподавателю: в отчёте используется номер группы.

## Сравнение

- **По словам и числам:** игнорируются разделяющие пробелы и переносы строк.
  Значения сравниваются как текст: `1` и `1.0` различаются, регистр учитывается.
- **Точное:** пробелы и строки значимы. CRLF/CR приводятся к LF.
  В конце можно игнорировать один перенос строки (прежнее поведение),
  все переносы строк либо все пробельные символы.
- **Числа с погрешностью:** сравниваются соответствующие токены.
  Для чисел допускается `|actual - expected| <= max(abs_tol, rel_tol * |expected|)`.
  Оба допуска задаются отдельно от 0 до 1, поддерживается запись `1e-6`.
  Ноль означает отсутствие соответствующего допуска. Остальные слова должны совпадать,
  число токенов должно быть одинаковым. NaN и бесконечности не принимаются.
- **По словам — совместимость с environments:** перед разделением на слова
  удаляются символы CR; это сохраняет контракт исходных модулей при импорте.

## Файлы и лимиты

Ввод и эталон можно загрузить отдельными текстовыми файлами UTF-8 (BOM допустим).
Файл заменяет соответствующее текстовое поле при сохранении; пустой файл очищает его.
После ошибки проверки формы успешно прочитанные файлы остаются в текстовых полях,
поэтому повторно загружать их не требуется. Файлы с неверной кодировкой или превышением
размера нужно исправить и выбрать заново. При перестановке теста выбранные файлы
перемещаются вместе с ним.

- До 50 тестов, до 8 МиБ UTF-8 на поле, до 64 МиБ данных на задачу.
- Время: от 1 до 30 секунд на тест, по умолчанию 2 секунды.
- Вывод: от 1 до 8192 КиБ, по умолчанию 100 КиБ.
- В каждом тесте можно переопределить общие лимиты времени и вывода.
  Пустое значение означает использование общего лимита.

Предел HTTP-запроса редактора — 130 МиБ, чтобы принять сохранённый текст вместе
с заменяющими файлами. Он повышается только на маршрутах записи задач после
проверки роли преподавателя. Если перед приложением стоит reverse proxy,
его лимит тела запроса для этих маршрутов должен быть не меньше 130 МиБ
(например, `client_max_body_size 130m` в Nginx). Конфигурации такого прокси в репозитории нет.

## Перенос существующих задач

В редакторе задач **2593–2600, 2605, 2611, 2636** доступна кнопка
**Загрузить исходные тесты из environments**. Она открывает форму с исходными
данными, не меняя задачу в базе. Перед переходом сохраните нужные изменения текущей формы.

Импорт сохраняет ввод, эталоны, сравнение, лимиты и начисление баллов:
для одной группы выбирается «Всё или ничего», для нескольких — группы по 5 баллов.
Все импортированные тесты изначально приватные. Для этих задач требуется C++
и исходный максимальный балл; несовместимые параметры отклоняются.
После просмотра и при необходимости изменения видимости нажмите **Сохранить**.
Существующие решения не перепроверяются автоматически: для этого есть отдельный флажок.

Другие environments автоматически не переносятся. Проверки функций, структуры кода,
памяти и неоднозначных ответов требуют отдельного анализа.

## Хранение и запуск

Набор хранится в `tasks.test_config`, режим — в `tasks.test_mode`.
Старые настройки без новых полей сохраняют прежнее поведение: пропорциональная
оценка, 100 КиБ вывода, один игнорируемый завершающий перенос при точном сравнении.
Переключение на environments или GPT сохраняет ранее настроенный набор.

Каждый тест запускается в новом контейнере без сети, с ограничениями ресурсов
и без файлов из environments. Это исключает перенос приватного ввода в следующий
публичный тест через файлы или фоновые процессы. Эталоны сравниваются вне контейнера.
Дополнительные Python-пакеты не устанавливаются.

## Развёртывание и проверка

Перед запуском обновлённых web и Celery примените миграции штатным способом:

```bash
flask --app manage db upgrade
```

В Docker Compose используйте сервис `migrate` из существующей схемы развёртывания.
Миграция `a8c2e4f6b901` добавляет настройки проверки; группы, загрузка файлов и
погрешность используют тот же JSON и дополнительной миграции не требуют.
Миграция не переключает существующие задачи и не изменяет решения или баллы.

```bash
python -m pytest -q tests/test_io_tests.py tests/test_schema_migrations.py tests/test_runner_harness.py tests/test_test_score_normalization.py
RUN_IO_DOCKER_INTEGRATION=1 python -m pytest -q tests/test_io_tests.py::IODockerTests
```

Тесты проверяют, в частности, совпадение баллов импортированных задач с environments
при полном успехе, отказе каждого отдельного входа и полном отказе.
Интеграционный прогон требует работающего Docker и образов Python/GCC.
