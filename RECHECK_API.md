# API для перепроверки задач

## Запрос ученика преподавателю

Кнопка «Попросить перепроверить» под результатом решения — отдельный механизм,
не запускающий автопроверку и не меняющий оценку.

- `GET /submission/recheck?id={CODE_ID}` — статус обращения в CodingProjects.
- `POST /submission/recheck?id={CODE_ID}` — JSON `{"comment": "..."}`,
  комментарий после обрезки краевых пробелов — 10–1000 символов.
- Нужна сессия **автора** решения; роль преподавателя не заменяет владение.
  POST требует заголовок `X-CSRF-Token` со значением из формы.
- GeekPaste вызывает `POST /api/geekpaste/recheck/status` или
  `POST /api/geekpaste/recheck` на CodingProjects. Автор, задача, курс и URL
  решения берутся из БД GeekPaste и подписываются HS256-токеном на 60 секунд
  (`purpose=solution-recheck`, `aud=codingprojects`). Токен не передаётся браузеру.
- CodingProjects хранит `recheck_requested` и `recheck_comment` в существующем
  решении, возвращает его в очередь преподавателя и отправляет обычное
  уведомление. Собственная форма CodingProjects использует тот же сервис.
  Повторный запрос до рассмотрения не меняет комментарий и не дублирует уведомление.
- Не принимаются запросы для чужих, ещё не оценённых, заблокированных задач
  и задач с полным баллом в этом курсе. При недоступности API показывается
  ошибка с возможностью повтора; текст комментария сохраняется в форме.

Новых переменных окружения и миграций БД не требуется: используются `SUBMIT_URL`,
`APP_URL`, существующий общий `JWT_SECRET` и поля обращений CodingProjects.

## Повторный запуск автопроверки преподавателем

Для отправки задачи на перепроверку необходимо выполнить POST-запрос на endpoint `/recheck` с указанием ID кода в query-параметре.

## Endpoint

```
POST /recheck?id={CODE_ID}
```

## Параметры

- **id** (обязательный, query-параметр) — ID кода/решения задачи, которое нужно перепроверить

## Требования

- Пользователь должен быть авторизован
- Пользователь должен иметь роль `teacher` или `admin`
- Код с указанным ID должен существовать
- Код должен быть привязан к задаче (иметь `task_id`)

## Ответ

При успешном выполнении:
- Код: 302 (редирект)
- Перенаправление на `/?id={CODE_ID}`
- Flash-сообщение: "Задача отправлена на повторную проверку."

При ошибке:
- 403 — пользователь не является преподавателем
- 302 с flash-сообщением "Код не найден." — код с указанным ID не существует
- 302 с flash-сообщением "Это не решение задачи." — код не привязан к задаче

## Пример запроса

```bash
curl -X POST 'https://paste.geekclass.ru/recheck?id=ABC123' \
  -H 'Cookie: session=...' \
  -L
```

## Что происходит при перепроверке

1. Сбрасываются результаты предыдущей проверки:
   - `check_state` → `'not checked'`
   - `check_points` → `0`
   - `check_comments` → `None`
   - `checked_at` → `None`

2. Запускается асинхронная задача проверки через Celery

3. Проверка выполняется в зависимости от типа задачи:
   - `tests` — проверка через тесты
   - `gpt` — проверка через GPT
